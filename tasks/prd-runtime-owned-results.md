# PRD: Capture worker results without mandatory report files

Status: guarded foundation and initial regular-file integration journal implemented; slice 1 remains incomplete and publicly disabled.

Parent scope: [package PRD](prd-package-delegate-graph.md). Design: [autonomous swarms](design-autonomous-swarms.md). Machine-readable intake: [issue JSON](intake-runtime-owned-results.json).

## Problem and user story

Worker collection currently couples authored report validation, AgentFS export and ledger auditing. A report-format error can spend a repair turn, while a bookkeeping failure after export can reject work that already changed the workspace. Coding and research need durable authored output and explicit task acceptance without a mandatory report file.

As a Pi user, I want useful worker results retained and assessed directly, so that report formatting cannot discard work or spend another model turn.

## Scope and compatibility

Add a frozen per-run `resultContract` enum: `legacy-v1 | runtime-v1`. The public tool's `op=init` operation accepts `resultContract`; `/delegate` accepts `--result-contract legacy-v1|runtime-v1` alongside its leading policy flag. `/graph` currently has inspection/recovery commands, not a creation subcommand. Omission selects `legacy-v1`. Unknown values fail before run creation or dispatch. `runtime-v1` is initially eligible only for build and research; operational-command runs keep their existing execution-proof contract and reject the new option explicitly. Preserve `/delegate`, `/graph`, and `delegate_graph` entry points.

### Guarded foundation increment

Durable output wiring: permit the public-output parser to bind an initially unknown request ID only from the first matching `session/prompt` inside the exact ensured ACP session. Persist original public text and per-chunk provenance incrementally in private files, separately from bounded raw stdout/stderr. Seal capture metadata and actual process outcome without consulting any report file. The worker runtime-v1 branch uses this collector; the public activation gate remains closed until each adapter's observed final-response semantics is verified. Process output files are created exclusively so replay cannot truncate an existing attempt.

Implement schema v6, immutable attempt registration and process-outcome/candidate persistence, content verification, and a bounded ACP public-output collector first. Package-private store methods may exercise `runtime-v1` using real temporary SQLite/filesystem resources; public initialization and dispatch remain disabled with a specific prerequisite error until actual adapter proof, worker lifecycle wiring, integration recovery and independent acceptance are complete. Do not permit legacy `record` or recovery calls to complete or redispatch a new-contract operation. Cancellation and read-only inspection remain available. This is an explicit activation gate, not an environment-variable bypass or a research-only release.

The capture helper retains attributed public text, never claims to identify a final answer based on an unverified adapter, and labels semantic response completeness unverified. It bounds event buffering at 1 MiB and total input at 16 MiB by default; overruns and malformed/ambiguous identity record incomplete capture. These are private helper limits until lifecycle wiring exposes supported configuration. Candidate records remain unaccepted; no decision or graph advancement API is enabled in this increment. The later work in this issue remains required and unchecked.

## Durable result contract

Use typed, discriminated records with database constraints. The exact SQL migration belongs to implementation, but these identities and state distinctions are required:

- **Attempt:** immutable run ID, operation ID, attempt key, selected agent/model, ACPX session and request identity, AgentFS session, timestamps and contract. Process state is `running | exited | cancelled | failed | interrupted`; termination includes exit/signal and failure cause when known. Unknown post-crash process state requires reconciliation, not a guessed clean exit. Cleanup has its own recorded state and may remain pending after process settlement.
- **Answer:** attempt-bound private content reference, digest, byte count, chunk ordering and public-output provenance; completeness is `complete | incomplete`. Retain original authored output independently of any parsed envelope. Do not call an arbitrary public progress chunk the final answer. A verified adapter must delimit the relevant response and record ambiguity as incomplete.
- **Candidate:** immutable ID and digest, attempt key, kind `coding | research | mixed`, answer/artifact references and validation findings. Coding also records base revision, changed-path inventory, ownership audit and content digests. Research retains findings, accessible retrieved material/provenance where available, and source references. No repository diff is required for research.
- **Decision:** immutable ID, candidate ID/digest, decision author, rationale, evidence references and disposition `accept | correct | block`. Coding acceptance binds the combined revision and check results; research acceptance binds the synthesis digest and independent source-support review. Replacing an assessment appends a new decision; it does not rewrite original output.

Attempt settlement and task completion are different transitions. Collecting a process outcome does not mark the operation completed or advance its graph node. Expose process outcome, pending acceptance, candidate ID and cleanup status through collection and status so a settled attempt is not presented as an executing worker. Extend `op=record` additively for new-contract decision/candidate references; retain its legacy report behavior. Commit a valid decision and graph transition in one conditional store transaction, checking the operation's active attempt and cancellation state. A stale candidate cannot advance a replacement attempt.

Stream output incrementally to mode-600 files in private mode-700 runtime directories, with bounded parser buffers, maximum event size and explicit total-output limits. Do not retain the full stdout/stderr stream in arrays as `runStreaming` currently does. Configure and document finite defaults during implementation. Reaching a limit records incomplete capture and preserves available data; it cannot become successful truncation. Never ingest thoughts, tool stdout or unrelated request output as authored answers. Research tool output may be retained separately as evidence with its own provenance, not promoted to assistant speech.

SQLite transactions cannot atomically commit external files. Write and flush immutable private content first, publish it by atomic rename, then transactionally register its digest/reference and attempt outcome. A crash before registration leaves a recoverable orphan, not accepted work. Verify referenced content before decisions. Essential persistence failure pauses dependent progress, retains the attempt resources needed for recovery and still attempts safe credential cleanup. No workspace mutation or redispatch follows an uncommitted outcome. On restored storage, reconcile the same attempt before launching a replacement.

Audit and extract from a disposable private copy of the closed snapshot, while checking that the authoritative original remains byte-exact. Do not misclassify the CLI's private journal creation as worker mutation or relax the source snapshot's closed-state requirement.

Flush prepared content in private staging, atomically rename into the workspace, and sync both parent directories. A pre-rename crash can safely discard/rebuild its private incomplete staging file from retained content without touching an unrecognized workspace file. ### Fenced attempt replacement — 2026-09-12 (Claude Code session, after the lifecycle wiring)

Scope: retry and model fallback for runtime-v1 attempts under the frozen policy, without reusing legacy `record`, `resolveExhaustion` or any report path. Nothing here decides a candidate or advances a graph.

- **Schema v8.** `runtime_attempts` loses its `operation_id UNIQUE` constraint (table rebuild, foreign keys off, checked after) and gains `superseded_at`; a partial unique index keeps exactly one active attempt (`superseded_at IS NULL`) per operation. Superseded rows remain immutable, keep their retained candidate/decision, and `runtimeAttempt(attemptKey)` still reads them. `next()`, `runtimeAttemptByOperation` and duplicate registration consult the active attempt only. Migration seeds for v1–v7 preserve rows; version assertions move to 8.
- **`GraphStore.retryRuntimeAttempt({ runId, operationId, error?, retryReason?, approved? })`** is the only replacement path. Automatic mode is fenced: the run must be active, the operation current and either (a) carrying a settled, undecided active attempt whose outcome is `failed` or `interrupted` (its recorded error text is classified; a caller-supplied `error` is refused), or (b) pending with no active attempt and a caller-supplied launch/preflight `error`. An attempt that is still running, exited (must be decided), cancelled, or already decided is refused. Classification reuses `classifyFailure`/`selectModelFallback`/`retryDelayMs` and the same bounds as legacy: transient and `transient_attempts < 3` → same model, `transient_attempts + 1`; otherwise transient with a next chain model and no exact lock → `model_attempt + 1`, transient reset; otherwise the operation is marked failed and the run parks `awaiting_user` with `retry_exhausted` or `operation_failed`. A replacement sets the operation back to `pending` with `agent_id`, `started_at` and `finished_at` cleared, `selected_model` from the frozen chain, `retry_not_before` from full-jitter backoff, and stamps the previous attempt `superseded_at`; events `runtime_attempt_superseded` plus the existing `retry`/`model_fallback` shapes are written in the same transaction. `approved: true` is the operator path from `awaiting_user` (operation `failed`, including a rejected candidate): the model attempt is kept, the transient counter advances by one so the replacement mints an attempt key and acpx session name never used before (the same-model budget is not restored), the operation returns to `pending`, and the run resumes `active` when nothing else at the node is unresolved.
- **Fence at registration.** `beginRuntimeAttempt` already derives its identity from the operation's `model_attempt`/`transient_attempts`; after a replacement the old identity is refused as conflicting with the operation and only the frozen next identity registers. The dispatch tool passes those counters to the worker, so the replacement's attempt key and acpx session name differ from the superseded one.
- **Tool surface.** `op=retry` (runtime-v1 only; legacy retries stay inside `record`) calls the automatic path; dispatch preflight failures on runtime-v1 runs go through it instead of legacy `record`; `op=resolve decision=retry` and `/graph resume` route runtime-v1 runs to the approved path. `defer`, `abort` and `escalate` remain refused for runtime-v1 (unchanged, still open). `decideRuntimeCandidate` refuses a superseded attempt.
